## 1. Полностью реализовать MQTT-протокол
Сейчас плеер принимает только `open` / `close`. Нужно:
- добавить остальные команды из контракта: `pause`, `resume`, `stop`, `seek`,

## 2. Экран настроек — ЧАСТИЧНО СДЕЛАНО (2026-07-06)
Сделано: экран настроек (кнопка «Настройки» с главного экрана) + хранение в
`SharedPreferences` (`Settings.kt`). Поля: URL Prism, адрес брокера MQTT
(+ логин/пароль), отображаемое имя. Идентификатор плеера генерируется автоматически
(`UUID`; в debug — `emulator`) и **не редактируется**. При пустых/битых настройках
плеер не подключается/не играет, но не падает (валидацию ввода на экране не делаем).
Применение — перезапуск `MqttService` при сохранении. Константы адресов вынесены из
`MqttController`/`MqttService` в `Settings.kt`.

Осталось:
- **автозаполнение настроек**: получать предзаполненный набор настроек, чтобы
  пользователю не вводить всё руками. Продумать удобный способ (варианты:
  QR-код / ссылка-приглашение / discovery в сети / дефолты от координатора).
  Требует отдельного обсуждения.

## 3. Фон / автозапуск по загрузке — СДЕЛАНО (2026-07-03)
Две службы (чтобы не конфликтовали за «передний план»):
- **`MqttService`** — всегда-живая служба переднего плана: MQTT + «пульт»
  (`MediaController`) к плееру; своё постоянное уведомление (не пропадает),
  `START_STICKY`, `onTaskRemoved` — живёт после закрытия приложения;
- **`PlaybackService`** (`MediaSessionService`) — плеер + сессия; Media3 сама рулит
  медиа-уведомлением;
- `BootReceiver` стартует `MqttService` по `BOOT_COMPLETED`;
- активация экрана из фона по `open` через `startActivity` + разрешение
  `SYSTEM_ALERT_WINDOW` (пользователь выдаёт один раз). См. README, раздел
  «Фон, автозапуск и активация». Два уведомления при игре — так задумано.
