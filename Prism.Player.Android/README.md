# Prism.Player.Android

Нативный плеер под **Android TV** — «исполнитель» (renderer) в архитектуре Prism.
Играет видео по присланному **абсолютному URL** (HLS), управляется локально пультом
через **MediaSession** и внешне — по **MQTT** (универсальный API управления, туда же
репортит состояние). **Не привязан к конкретному хосту** — URL приходит в команде,
поэтому источников контента может быть несколько; самодостаточен через пульт
Android TV; координация (напр. ThinkingHome) — снаружи, по MQTT.

## Роли в системе

- **Prism.Host** — источник: стриминг (HLS), библиотека и метаданные. Про
  воспроизведение не знает.
- **Prism.Player.Android** (этот проект) — рендерер: декодирует и показывает,
  держит состояние play/pause/позиция, принимает команды.
- **Координатор** (ThinkingHome и др.) — снаружи, шлёт команды и читает состояние
  по MQTT. Своего протокола нет — только стандартный MQTT + этот контракт.

## Стек

- **Kotlin**, **Media3/ExoPlayer** — воспроизведение HLS (переключение дорожек/
  субтитров/скорости — на будущее, см. TODO);
- **`PlaybackService`** (`MediaSessionService`) — проигрыватель + медиа-сессия;
  Media3 сама показывает медиа-уведомление (управление пультом/CEC/ассистентом);
- **`MqttService`** — всегда-живая служба переднего плана: MQTT-клиент + «пульт»
  (`MediaController`) к плееру; своё постоянное уведомление;
- **UI на обычных Android View** (без Compose): тёмная плоская тема (`AppTheme`,
  против выгорания ТВ, фон `#282828`); главный экран (логотип + кнопка-шестерёнка
  «Настройки» в углу + статус брокера) + экран плеера (видео на весь экран, фон под
  видео **чёрный** — иначе поля по краям кадра светились бы серым); навигация
  D-pad. Обзора библиотеки в самом плеере
  нет — это дело координатора/веб-клиента.
- иконка + TV-баннер (`LEANBACK_LAUNCHER`) — приложение видно на домашнем экране Android TV.
- **Локализация RU/EN** — строки в `res/values/strings.xml` (англ., по умолчанию) и
  `res/values-ru/strings.xml`; язык подхватывается по системному (стандартный Android
  i18n, без кода/выбора языка в приложении).

## Конфигурация

Плеер **не привязан к конкретному хосту**: что играть, приходит в команде `open`
абсолютным URL (см. контракт ниже), поэтому источников контента может быть несколько
(медиатека, видеонаблюдение и т.п.).

Настройки редактируются на **экране настроек** (кнопка «Настройки» на главном
экране) и хранятся в `SharedPreferences` (см. `Settings.kt`). Поля:

- адрес брокера **MQTT** (+ логин/пароль при необходимости);
- **отображаемое имя** плеера (напр. «Гостиная»).

**Идентификатор плеера** `{id}` не редактируется: генерируется один раз (`UUID`) и
хранится; из него выводятся топик команд `prism/player/{id}/cmd` и client-id
подключения. В отладочной сборке `{id}` = `emulator` (удобно для тестов), и туда же
подставляется дефолтный адрес брокера `tcp://10.0.2.2:1883`; в release-сборке поля
пустые до первой настройки. При пустых/битых настройках плеер не подключается/не
играет, но не падает. Изменения применяются перезапуском `MqttService` при сохранении.

## Ошибки и статус связи

- **Брокер недоступен:** плеер переподключается бесконечно (интервал ~5 с) в одном
  потоке, без накопления ресурсов; после первого коннекта обрывы держит
  единый цикл подключения с повторной подпиской на топик. Отдельного диалога нет —
  состояние показывает статус-надпись (ниже). Так приставка не выпадает из
  управления при кратком сбое брокера.
- **Статус MQTT** — мелкая надпись у нижнего края стартового экрана:
  «MQTT: подключено» / «MQTT: нет связи» (при воспроизведении скрыта).
- **Хост/поток недоступен** (или неверный `url`): ExoPlayer отдаёт ошибку —
  показываем надпись «Не удалось открыть видео» поверх видео и больше ничего не
  делаем; она исчезает при следующем `open`.

## MQTT-контракт управления

Префикс `prism`, `{id}` — идентификатор плеера. Пейлоады — JSON (UTF-8).

### Плеер → брокер

| Топик | Назначение | Retain |
|-------|-----------|:------:|
| `prism/player/{id}/info` | статичная инфа о плеере | да |
| `prism/player/{id}/state` | текущее состояние (при изменениях + позиция) | да |
| `prism/player/{id}/event` | разовые события | нет |

Поля `info`: `name` — отображаемое имя; `capabilities` — что поддерживает плеер.
Адрес хоста плеер НЕ хранит — абсолютный URL приходит в команде `open`.

```jsonc
// info
{"name":"Гостиная","capabilities":["open","close","refresh"]}

// state (retained); title / произвольная meta — позже (см. TODO)
{"status":"playing",           // idle | buffering | playing | paused | ended
 "url":"http://host/hls/abc123/playlist.m3u8","positionSec":123.4,"durationSec":2555.1}

// event (пока не реализовано)
{"type":"ended","url":"http://host/hls/abc123/playlist.m3u8"}
{"type":"error","message":"..."}
```

### Брокер → плеер (команды публикует координатор)

Топик `prism/player/{id}/cmd`, пейлоад — JSON:

```jsonc
{"action":"play","url":"http://host/hls/abc123/playlist.m3u8","positionSec":0,"audio":0,"subtitle":null}
{"action":"pause"}
{"action":"resume"}
{"action":"stop"}
{"action":"seek","positionSec":120}
{"action":"next"}                      // следующая серия
{"action":"previous"}                  // предыдущая серия
{"action":"setAudio","index":1}
{"action":"setSubtitle","index":0}     // отсутствует/null = выкл
{"action":"setRate","rate":2.0}
{"action":"refresh"}                   // немедленно перепубликовать info + state
```

- `info` и `state` — **retained**: поздно подключившийся координатор сразу видит, кто
  есть и что играет. Ливность плеера — по свежести периодического `state` (отдельного
  `availability`/LWT нет); при желании координатор шлёт команду `refresh` для
  немедленного ответа.
- Обнаружение плееров — подписка на `prism/player/+/info` и `prism/player/+/state`.
- Команды MQTT и локальный пульт/ассистент идут в **один и тот же** внутренний
  контроллер плеера — единый путь управления.
- **Сейчас реализованы** `open` / `close` / `refresh`; остальные команды — по
  `TODO.md` п.1.

### Поток «включи фильм X»

1. Координатор (TH) резолвит название → **абсолютный URL потока**: `/api/media`
   возвращает `streamUrl` (напр. `/hls/{id}/playlist.m3u8`), координатор подставляет
   хост нужного Prism.
2. Публикует `{"action":"play","url":"http://host/hls/…/playlist.m3u8"}`
   в `prism/player/{id}/cmd`.
3. Плеер играет присланный URL, обновляя `state` (в нём и репортит этот `url`).

`next`/`previous` — «следующая/предыдущая серия»: поскольку плеер host-agnostic и не
знает библиотеку, соседний эпизод вычисляет **координатор** и шлёт его URL.

## Фон, автозапуск и активация

MQTT-служба использует тип `connectedDevice`: плеер получает команды от другого
устройства по сети и передаёт ему состояние. Разрешение `CHANGE_NETWORK_STATE`
выполняет системное условие для этого типа сетевого foreground service; приложение
не изменяет настройки сети. Тип `dataSync` больше не используется. Воспроизведение
по-прежнему обслуживает отдельный `PlaybackService` типа `mediaPlayback`.

- В настройках пользователь задаёт корректный адрес брокера, включает
  «Дистанционное управление» и нажимает «Сохранить». По умолчанию управление
  выключено, в том числе при обновлении с версии без этой настройки.
- Сначала служба публикует foreground-уведомление, затем подключает медиасессию и MQTT.
  Уведомление показывает подключение/ожидание команд, открывает плеер и содержит
  кнопку «Отключить управление». Отключение также доступно в настройках.
- Отключение сохраняется: открытие плеера и перезагрузка устройства не включают
  службу обратно. При выключении останавливаются соединение, повторные подключения,
  периодическая отправка статуса; воспроизведение ставится на паузу.
- Если управление включено и адрес корректен, `BOOT_COMPLETED` восстанавливает
  `connectedDevice`-службу. Системный запрет фонового запуска обрабатывается без
  падения; повторный запуск возможен при открытии плеера. После системного Force stop
  Android не доставляет приложению загрузочные события до ручного открытия.
- MQTT-клиент работает в одном сетевом потоке. После обрыва соединения он повторно
  подключается и подписывается; старые callbacks после остановки игнорируются.
  Ожидание подключения ограничено 5 секундами; очистка не блокирует главный поток.
- Команда `open` запускает видео только при видимом экране плеера. Если пользователь
  разрешил показ поверх других приложений, служба сначала пытается открыть экран.
  Иначе URL остаётся в памяти до открытия плеера через уведомление или иконку.
  Следующий `open` заменяет ожидающий URL, `close` отменяет его. Ожидающая команда
  не сохраняется при остановке службы или завершении процесса.
- Разрешение уведомлений запрашивается на Android 13+ при включении управления.
  При отказе управление остаётся доступно, но для ожидающего видео нужно открыть
  плеер вручную; остановка доступна в настройках.
- При сворачивании видео ставится на паузу. Двойной Back закрывает видео; позиции
  просмотра сохраняются для продолжения. Служба управления при этом остаётся
  активной до её явного отключения.

### Декларация Google Play и проверка на устройстве

В Play Console нужно задекларировать `connectedDevice` и `mediaPlayback` и приложить
видео работы функций. Для `connectedDevice` описать управление Android TV с другого
устройства через настроенный пользователем MQTT-брокер: включение в настройках,
ожидание немедленных команд, уведомление и отключение. Задержка или прерывание
соединения делает плеер недоступным для дистанционного управления. `mediaPlayback`
используется только при воспроизведении. Одобрение декларации принимает Google Play.

Проверить на Android TV (особенно Android 14/15/16):

1. Чистая установка: служба не работает до явного включения, неверный URL не сохраняется
   при включённом управлении. После подключения приходят `info` и `state`.
2. Home → `open`: с разрешением поверх других приложений экран открывается; без него
   видео не начинает играть в фоне и запускается после ручного открытия плеера.
3. «Отключить управление» в уведомлении и настройках: MQTT отключён, повторное открытие
   и перезагрузка его не включают. При включённой настройке перезагрузка восстанавливает
   соединение, но не запускает воспроизведение.
4. Потеря сети/перезапуск брокера: переподключение, повторная подписка, команды работают.
   Быстрое изменение настроек и выключение во время подключения не вызывают падений.
5. Разрешённые/запрещённые уведомления, работа с пультом, ожидание команд свыше 6 часов.

Проверка MQTT на локальном тестовом брокере: `./gradlew.bat testDebugUnitTest`.
Тесты проверяют подписку, повторное подключение, закрытие сокета, остановку во время
подключения и отбрасывание запоздавших callbacks. Они не заменяют проверку Android TV.

Источники: [типы foreground services](https://developer.android.com/develop/background-work/services/fgs/service-types),
[фоновые запуски](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start),
[декларация Google Play](https://support.google.com/googleplay/android-developer/answer/13392821).

## Сборка

### Google Play

Название приложения: **ThinkingHome Prism Player**. Идентификатор для Google Play:
`ru.thinking_home.prism.player` (отличается от прежнего `org.prism.player`, поэтому
установка считается отдельным приложением). Namespace исходников остаётся прежним.

Для загрузки в Play Console нужен подписанный AAB. Из папки проекта в PowerShell:

```powershell
./gradlew.bat bundleRelease lintRelease '-PreleaseVersion=0.4.1' '-PreleaseVersionCode=7'
```

Результат: `app/build/outputs/bundle/release/app-release.aab`. Для следующего выпуска
задайте versionCode больше всех ранее загруженных в Play Console. Release использует
существующий ключ из `keystore.properties`; перед сборкой убедитесь, что файл и ключ
доступны. Не загружайте ключ или конфигурацию с паролями вместе с AAB.

Для переноса подписи на другой компьютер положите ключ `prism-release.jks` и
переносимый `keystore.properties` с `storeFile=prism-release.jks` в корень этого
Android-проекта. Оба файла исключены из Git. Ключ подписи приложения в Google Play
App Signing выбирается отдельно в консоли; локальный ключ может служить ключом загрузки.

Успешная сборка и lint не заменяют проверку на Android TV и модерацию Google Play.

Политика конфиденциальности: `docs/player-privacy.md` для сайта и
`app/src/main/assets/privacy-en.txt` / `privacy-ru.txt` для встроенного экрана.
При изменении текста обновляйте все три файла согласованно. Экран открывается
из настроек, работает без браузера и интернета. После публикации сайта адрес
для Play Console: `https://prism.thinking-home.ru/player-privacy`.

### Локальная сборка

Требуется Android Studio / Android SDK (платформа 36, Build Tools 36.0.0 и `adb`).
Оба Android-проекта собираются на **JDK 25**: Gradle Wrapper 9.1.0,
Android Gradle Plugin 9.0.1 и встроенный Kotlin 2.3.0. `JAVA_HOME` должен
указывать на JDK 25 (например, `jbr` в установленной Android Studio),
`ANDROID_HOME` — на Android SDK. Уровень байткода остаётся Java 17;
минимальная версия Android не меняется. Сборка из терминала:

```bash
./gradlew assembleDebug        # debug-APK (для тестов; id=emulator, дефолты 10.0.2.2)
./gradlew installDebug         # установить debug на подключённое устройство/эмулятор
```

**Debug vs release.** В debug-сборке `id` плеера зашит как `emulator`, а поля настроек
предзаполнены адресами эмулятора (`10.0.2.2`) — удобно для тестов, но НЕ для продакшена
(несколько устройств получат одинаковый `id`). **Release-сборка** даёт уникальный
`UUID`-id и пустые поля — её и ставим на приставки:

```bash
./gradlew assembleRelease      # → app/build/outputs/apk/release/app-release.apk
```

Подпись release настроена через `keystore.properties` (в корне Android-проекта, НЕ в
git) и keystore `prism-release.jks`. Если файла настроек подписи нет, сборка создаёт
`app-release-unsigned.apk`: перед установкой его нужно подписать прежним ключом.
Библиотека Android читает такой же `keystore.properties` из корня своего проекта.
Оба приложения могут использовать один постоянный ключ: путь `storeFile` задаётся
относительно корня соответствующего Android-проекта. Локальный ключ Prism находится
в `data/signing/prism-release.jks` в корне репозитория; ключ и оба файла настроек
подписи исключены из git. Для резервной копии нужны все три файла.
**Храни `prism-release.jks` в надёжном месте:** без
того же ключа обновление поверх установленного приложения не встанет (подпись обязана
совпадать). Иконка (`app-icon.png`) и TV-баннер уже в манифесте — приложение появляется
на домашнем экране Android TV.
