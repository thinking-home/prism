## Context

Prism уже включает `Prism.Player.Android` — отдельный Gradle-проект (Kotlin,
традиционные Android Views, без Compose), namespace `org.prism.player`,
`minSdk 24`/`compileSdk 36`, свой `settings.gradle.kts` вне решения .NET
(`Prism.sln`). Это host-agnostic плеер-приёмник команд по MQTT: своего HTTP к
библиотеке не делает и структуру библиотеки не знает.

`Prism.Library` уже отдаёт всё, что нужно новому приложению, без изменений:
`GET /api/library/tree` (все группы и членство одним запросом),
`GET /api/media` / `GET /api/media/{id}` (агрегированный каталог с мета,
`present`, `playable`), `GET /api/players`, `POST /api/players/{id}/open`. См.
`proposal.md` — мотивация и список возможностей; поведенческие требования — в
`specs/library-android/*`.

## Goals / Non-Goals

**Goals:**
- Отдельный Android-проект `Prism.Library.Android`, не зависящий от
  `Prism.Player.Android` и не требующий его наличия на устройстве (и наоборот).
- Один и тот же UI работает и на телефоне (касание), и на Android TV (D-pad),
  без раздельных экранов под платформу.
- Минимальный набор новых зависимостей и минимальное отклонение стиля кода от
  `Prism.Player.Android`, чтобы оба приложения были одинаково просты в
  поддержке одному разработчику.

**Non-Goals:**
- Поиск (вынесен в отдельное будущее изменение, см. `proposal.md`).
- Управление воспроизведением с этого приложения (пауза/перемотка и т.п.) —
  оно только запускает воспроизведение на плеере, дальше плеером не управляет.
- Discovery/автозаполнение адреса библиотеки — только ручной ввод URL (как и
  решено для единственной настройки).
- Общий переиспользуемый код между `Prism.Library.Android` и
  `Prism.Player.Android` (общий Gradle-модуль, shared-библиотека) — оба
  приложения самостоятельны; если позже появится реальное дублирование,
  выносить общее — отдельное решение.

## Decisions

- **Отдельный Gradle root-проект `Prism.Library.Android`**, сиблинг
  `Prism.Player.Android` в корне репозитория, со своим `settings.gradle.kts`
  (не модуль внутри `Prism.Player.Android`, не часть `Prism.sln`). Совпадает с
  тем, как уже организован плеер; позволяет ставить/собирать приложения
  независимо. `applicationId`/namespace — `org.prism.library` (по аналогии с
  `org.prism.player`), отдельная иконка и лаунчер-баннер — приложения различимы
  на домашнем экране ТВ и в списке приложений телефона.
- **Традиционные Android Views (не Jetpack Compose)** — тот же стиль, что и у
  `Prism.Player.Android`. Alternative considered: Compose (в т.ч. Compose for
  TV) даёт более декларативную работу с фокусом, но добавляет второй стиль UI
  в кодовую базу с одним активным разработчиком и без реальной необходимости —
  список папки и шторка с действиями не настолько сложны, чтобы это окупалось.
  Фокус для D-pad на обычных `View`/`RecyclerView` работает из коробки при
  `focusable="true"` и корректном порядке элементов — специальной библиотеки
  (Leanback) не требуется.
- **Один Activity, список текущей папки — `RecyclerView` внутри фрагмента/вью,
  стек посещённых узлов — простой список id в памяти Activity** (не
  Navigation Component). Переход в группу — `push` id группы и перезагрузка
  списка; системная кнопка «назад» — `pop` последнего id (пустой стек =
  корень, дальше `pop` недоступен, «назад» ведёт себя как обычно). Отдельной
  кнопки/стрелки «наверх» в интерфейсе нет — это единственный способ подняться
  по папке, замечание пользователя на ревью шага 4 (стрелка налезала на
  список). Шторка с информацией о файле — `BottomSheetDialogFragment`
  (Material Components for Android); нажатие «назад» с открытой шторкой
  закрывает её, а не поднимается по папке (стандартное поведение диалогов,
  ничего писать вручную не требуется).
- **Шапка экрана с названием текущей папки** (замечание пользователя на
  ревью шага 4, вместо убранной кнопки «наверх»): фиксированная область
  сверху экрана над списком, показывает имя текущей группы или обозначение
  корня библиотеки; обновляется при каждом переходе в группу или подъёме
  наверх.
- **Иконки интерфейса — векторные drawable из одного набора**, не
  emoji-символы в тексте (замечание пользователя на ревью шага 4: emoji для
  группы/файла в списке заменить на иконки). Источник набора — уже
  существующая иконка настроек `ic_settings` в `Prism.Player.Android`
  (перенесённая без изменений в `Prism.Library.Android` на шаге 2): по факту
  это иконка из Material Design Icons, а не Lucide, как было ошибочно записано
  здесь ранее (замечание пользователя на дополнительном ревью: единообразие
  важнее конкретного названия набора). Новые иконки — папки и файла/видео —
  SHALL браться из того же набора Material Design Icons, тем же стилем (заливка
  `#FFFFFFFF`, `viewportWidth`/`viewportHeight` 24, для тёмной темы), чтобы все
  иконки приложения выглядели как один визуальный набор, согласованный с
  `Prism.Player.Android`.
- **HTTP и JSON**: OkHttp для запросов к `Prism.Library` +
  `kotlinx.serialization` для разбора ответов. Alternative considered:
  Retrofit — даёт готовые интерфейсы вызовов, но для пяти простых
  GET/POST-эндпоинтов это лишний слой генерации поверх того же OkHttp;
  голого OkHttp с ручным разбором достаточно и проще читать одному
  разработчику.
- **Список плееров и выбор при запуске** — простой список (диалог/шторка) по
  ответу `GET /api/players`, без запоминания «последнего использованного» и
  без авто-выбора при единственном плеере (в отличие от лаунчера — там это
  осознанное решение для сценария «Отправить», здесь пользователь и так
  дошёл до экрана выбора действия, дополнительная магия не обсуждалась и не
  нужна по умолчанию).
- **Хранение настройки адреса** — `SharedPreferences`, один текстовый ключ, по
  аналогии с `Settings.kt` в `Prism.Player.Android`, но без остальных полей
  плеера (брокер MQTT, id, имя) — они этому приложению не нужны.
- **Реализация — маленькими шагами, каждый на ревью пользователя** (решение
  пользователя на ревью плана): порядок шагов задаёт `tasks.md`, каждый шаг —
  минимальный, но цельный результат (пользователь может его увидеть/запустить),
  без функциональности сверх согласованной в рамках шага. Код обильно
  комментируется в расчёте на читателя, не пишущего код под Android (что делает
  каждый небольшой блок, а не только сигнатуры). Первый шаг — само приложение с
  текстом Hello World, без сети и без настроек, чтобы сразу проверить, что
  проект собирается и ставится на устройство/эмулятор.

## Risks / Trade-offs

- [Список папки на ТВ без выделенной TV-библиотеки (Leanback/Compose for TV)
  может потребовать более внимательной раскладки визуального фокуса руками] →
  проверять вживую на приставке по ходу реализации (как уже принято в проекте
  для `Prism.Player.Android`), а не полагаться только на эмулятор.
- [Два независимых приложения не переиспользуют код друг друга — потенциальное
  дублирование мелочей вроде базового HTTP-клиента, если позже появится ещё
  один Android-клиент] → осознанный компромисс ради простоты; выносить общее
  только по факту третьего случая или явного решения пользователя.

## Migration Plan

Не применимо — новое приложение, устанавливается отдельным APK, ничего
существующего не заменяет и не требует отключения.
