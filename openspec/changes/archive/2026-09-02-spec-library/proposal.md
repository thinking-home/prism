## Why

Проект Prism не имеет OpenSpec-спецификаций. Чтобы дальнейшие изменения
библиотеки (`Prism.Library` — сервис агрегации хостов, структуры и меты,
списка плееров и веб-клиента) можно было предлагать и ревьюить через
OpenSpec, нужна базовая спецификация, фиксирующая уже реализованное поведение.

## What Changes

- Задокументировать текущее поведение `Prism.Library` как baseline-
  спецификации: без изменения кода и без изменения поведения — только
  формализация того, что уже работает.
- Библиотека охватывает: агрегацию каталога нескольких хостов, дерево групп и
  свободную мету, правила автозаполнения, ремап отпечатков и обслуживание
  (GC), список плееров и включение фильма на плеере через MQTT, раздачу
  собранного веб-клиента.

## Capabilities

### New Capabilities
- `library/catalog-aggregation`: конфиг хостов (`Hosts`: имя + базовый URL),
  параллельный опрос хостов с таймаутом, слияние `GET /api/media` по
  контентному id (копия на двух хостах — одна запись, абсолютный `streamUrl`
  на хост-владельца, поля `host`/`hostUrl`), адресные запросы карточки файла и
  преемника (без опроса всех хостов), состояние `present:false` как для
  отсутствия файла на диске, так и для недоступности хоста.
- `library/tree-and-metadata`: дерево групп с вложенностью и членством файлов
  в нескольких группах (`Prism_Node`/`Prism_NodeItem`), свободная
  key-value мета файлов и групп (`Prism_Meta`), CRUD дерева (перенос ветки —
  смена родителя), `GET /api/library/tree` одним запросом без пагинации,
  `PUT/DELETE` меты (слияние ключей, null — удаление), подмешивание меты в
  агрегированный `/api/media`.
- `library/auto-rules`: правила автозаполнения по шаблону пути с
  плейсхолдерами (`{имя}`, `{имя:#}`, `*`), применяются только к файлам без
  единой записи в библиотеке, действия — узел дерева и/или мета-ключи,
  порядок правил и приоритет первого совпадения по ключу, режим `replace`
  (полная очистка и раскладка заново, только по запросу).
- `library/fingerprint-remap`: ремап осиротевших отпечатков по последнему
  известному пути (перенос меты/членства при неконфликтной замене
  содержимого), бухгалтерия «id → хост» для адресного поиска преемника,
  фоновая доразборка/ремап единым циклом обслуживания (ремап строго раньше
  правил), GC осиротевших записей и бухгалтерии по явному запросу.
- `library/players`: подписка на MQTT (`prism/player/+/info|state`),
  `GET /api/players` (имя, online-эвристика по свежести, статус/позиция),
  `POST /api/players/{id}/open` (адресный резолв файла в URL хоста-владельца и
  публикация команды в топик плеера), поведение при отсутствии брокера
  (503) и при неизвестном/невоспроизводимом файле.
- `library/web-client-hosting`: раздача собранного веб-клиента из
  сконфигурированной папки (`Client:Path`), same-origin по умолчанию, работа
  API как обычно при отсутствии папки клиента.

### Modified Capabilities
- (нет — в репозитории ещё нет ни одной спецификации)

## Impact

- Затронутый код: `Prism.Library`, `Prism.Library.Console` — только описание
  существующего поведения, изменений в коде эта задача не предполагает.
- Специфицируется только сервис библиотеки. Контракты хоста, которые
  библиотека потребляет (`/api/media`, `/api/resolve`, `/api/media/{id}/successor`),
  описаны отдельным изменением `spec-host`; протокол MQTT-команд плееру и
  сценарий отправки с лаунчера — изменением `spec-launcher`. Веб-клиент
  (`Prism.Client`) специфицируется вместе с библиотекой (клиент раздаётся ею
  и работает только с её API), отдельного изменения под клиент не заводим.
