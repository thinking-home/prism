## Purpose

Библиотека собирает файлы со всех сконфигурированных хостов в один каталог,
чтобы клиенты видели общую медиатеку сети, не зная об отдельных хостах, и
чтобы недоступность одного хоста не ломала работу с остальными.

## ADDED Requirements

### Requirement: Конфигурация хостов
Библиотека SHALL получать список хостов из конфигурации (секция `Hosts`: имя и
базовый URL каждого). Хост без имени SHALL представляться своим URL.

#### Scenario: Хост без явного имени
- **WHEN** в конфиге у записи хоста не задано имя
- **THEN** библиотека использует базовый URL хоста как его имя в каталоге

### Requirement: Слияние каталога всех хостов
`GET /api/media` SHALL опрашивать все сконфигурированные хосты параллельно и
возвращать объединённый список: копия одного и того же файла (по контентному
id) на нескольких хостах SHALL давать одну запись в ответе, приоритет — у
хоста, стоящего в конфиге раньше. Каждая запись SHALL содержать абсолютный
`streamUrl` (указывающий на хост-владельца), а также поля `host` (имя хоста) и
`hostUrl` (его базовый адрес).

#### Scenario: Один файл виден на двух хостах
- **WHEN** идентичное по содержимому видео присутствует на двух сконфигурированных хостах
- **THEN** в объединённом каталоге присутствует одна запись этого файла, атрибутированная первым по конфигу хостом

#### Scenario: Относительный streamUrl хоста становится абсолютным
- **WHEN** хост отдаёт запись с относительным `streamUrl`
- **THEN** в ответе библиотеки `streamUrl` этой записи — абсолютный адрес на этот хост

### Requirement: Недоступный хост не ломает выдачу каталога
Если хост не отвечает при опросе — его файлы SHALL быть исключены из
объединённого списка `GET /api/media`, а опрос остальных хостов SHALL
продолжаться независимо (недоступность одного хоста не должна задерживать или
прерывать ответ библиотеки дольше отведённого таймаута на этот хост).

#### Scenario: Один из хостов недоступен
- **WHEN** один из сконфигурированных хостов не отвечает на `GET /api/media`
- **THEN** объединённый каталог содержит файлы только доступных хостов, а ответ не зависает дольше таймаута опроса недоступного хоста

### Requirement: Адресный доступ к карточке одного файла
`GET /api/media/{id}` SHALL запрашивать карточку файла только у хостов, ранее
видевших этот id (по внутренней бухгалтерии «id → хост»), а не у всех
сконфигурированных хостов. Если ни один из известных для файла хостов не
отвечает или файл там больше не найден — ответ 404 (файл сейчас недоступен).

#### Scenario: Карточка файла запрашивается адресно
- **WHEN** запрошена карточка файла, ранее увиденного только на одном конкретном хосте
- **THEN** библиотека опрашивает только этот хост, не все сконфигурированные хосты

#### Scenario: Хост-владелец файла недоступен
- **WHEN** единственный хост, ранее видевший запрошенный файл, не отвечает
- **THEN** `GET /api/media/{id}` отвечает 404

### Requirement: Мета из БД подмешивается поверх данных хоста
И в объединённом каталоге, и в карточке одного файла ключи свободной меты,
хранящиеся в библиотеке, SHALL накладываться поверх одноимённых полей,
пришедших от хоста (мета побеждает).

#### Scenario: У файла задан мета-ключ title
- **WHEN** у файла в библиотеке сохранён мета-ключ `title`, отличный от имени файла на хосте
- **THEN** в ответе `GET /api/media` и `GET /api/media/{id}` значение `title` — из меты библиотеки
