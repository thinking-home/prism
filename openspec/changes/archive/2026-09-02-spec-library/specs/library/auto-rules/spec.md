## Purpose

Библиотека умеет автоматически раскладывать новые файлы по группам и
проставлять им мету по декларативным правилам-шаблонам пути, чтобы не
требовать ручной разметки каждого файла.

## ADDED Requirements

### Requirement: Правило — шаблон пути с плейсхолдерами
Правило SHALL задаваться шаблоном относительного пути файла (без расширения) с
плейсхолдерами `{имя}` (непустой кусок одного сегмента пути), `{имя:#}`
(только цифры) и `*` (любой кусок сегмента, включая пустой, без захвата
значения), сопоставляемым без учёта регистра. Правило SHALL задавать хотя бы
одно действие: путь узла дерева (с плейсхолдерами) и/или мета-ключи со
значениями-шаблонами.

#### Scenario: Правило с плейсхолдером и мусором вокруг
- **WHEN** задано правило с шаблоном, включающим `*` до и после значимого плейсхолдера
- **THEN** правило совпадает с путями, где вокруг значения есть произвольный посторонний текст

#### Scenario: Правило без действий игнорируется
- **WHEN** в конфигурации задано правило без узла дерева и без мета-ключей
- **THEN** правило не применяется ни к одному файлу

### Requirement: Правила применяются только к нетронутым файлам
Автозаполнение SHALL применяться только к файлам, у которых нет ни одной
записи в библиотеке — ни меты, ни членства в группе, независимо от того, как
эта запись появилась (от правила или вручную). Файл, полученный по правилу,
после ручной правки (включая частичное удаление меты) SHALL считаться
тронутым и больше не переобрабатываться правилами. Полное удаление всех
записей файла SHALL возвращать его в состояние «нетронутый» — при следующем
проходе он снова раскладывается по правилам.

#### Scenario: Ручная правка не откатывается
- **WHEN** файл разложен правилом, а затем пользователь вручную меняет его мету
- **THEN** последующие проходы автозаполнения не трогают этот файл

#### Scenario: Полный сброс записей файла
- **WHEN** у файла удалены все записи меты и членства
- **THEN** ближайший проход автозаполнения раскладывает файл заново по правилам

### Requirement: Порядок применения правил и приоритет мета-ключей
Все подходящие по шаблону правила SHALL применяться к файлу; при совпадении
имени мета-ключа у нескольких правил SHALL побеждать значение первого
подходящего правила по порядку в конфигурации. Узлы дерева, назначенные
разными подходящими правилами, SHALL добавляться все (файл может попасть
сразу в несколько групп).

#### Scenario: Два правила задают один мета-ключ
- **WHEN** путь файла подходит под два правила, оба из которых задают мета-ключ `title`
- **THEN** сохраняется значение от правила, идущего в конфигурации раньше

### Requirement: Полная переразметка библиотеки по запросу
`POST /api/library/scan?replace=true` SHALL по явному запросу полностью
очищать библиотеку (все группы, всё членство, всю мету — включая записи
файлов, отсутствующих сейчас на хостах) и раскладывать все текущие файлы
заново по правилам. Такая очистка SHALL выполняться самим фоновым циклом
обслуживания в начале его ближайшего прохода, а не немедленно в обработчике
запроса — чтобы не конфликтовать с проходом, который уже мог идти в этот
момент. Автоматически (по таймеру) такая очистка SHALL не запускаться.

#### Scenario: Запрошена переразметка
- **WHEN** отправлен `POST /api/library/scan?replace=true`
- **THEN** библиотека полностью очищается и раскладывается заново в ближайшем проходе фонового обслуживания, ответ на запрос не ждёт завершения прохода

#### Scenario: Переразметка не запускается сама по себе
- **WHEN** проходит очередной плановый проход обслуживания без запроса `replace=true`
- **THEN** существующие группы, членство и мета не очищаются
