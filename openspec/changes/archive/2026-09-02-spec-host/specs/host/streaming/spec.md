## Purpose

Хост выбирает для каждого файла способ доставки видео и раздаёт его клиенту:
напрямую (для браузерных форматов) либо через генерируемый на лету HLS с
несколькими дорожками аудио и субтитров — так, чтобы перемотка двухчасового
файла и переключение дорожек работали без перекодирования лишнего.

## ADDED Requirements

### Requirement: Выбор режима воспроизведения
Хост SHALL определять для каждого файла один из режимов: `direct` (контейнер и
кодеки уже поддерживаются браузером — mp4/webm с h264/vp9/av1 + aac/opus и т.п.),
`hls` (нужна перекодировка, и она возможна — есть подходящий декодер ffmpeg) или
`unsupported` (нужна перекодировка, но она невозможна: ffmpeg недоступен или
исходный кодек не поддерживается декодером). Режим SHALL передаваться клиенту в
поле `streamType`, и `playable` SHALL быть `true` только для `direct` и `hls`.

#### Scenario: Браузерный mp4 раздаётся напрямую
- **WHEN** файл в контейнере mp4 с кодеками h264 и aac
- **THEN** `streamType` равен `direct`, `streamUrl` указывает на `/raw/{id}`

#### Scenario: Файл с неподдерживаемым кодеком идёт через HLS
- **WHEN** файл в контейнере, который браузер не воспроизводит напрямую, и в системе есть нужный декодер ffmpeg
- **THEN** `streamType` равен `hls`, `streamUrl` указывает на `/hls/{id}/playlist.m3u8`

#### Scenario: Перекодировка невозможна
- **WHEN** файлу нужна перекодировка, но ffmpeg недоступен или не может декодировать исходный кодек
- **THEN** `streamType` равен `unsupported`, `playable` равен `false`, `streamUrl` равен `null`

### Requirement: Прямая раздача с поддержкой Range
Для файлов в режиме `direct` хост SHALL отдавать содержимое по `GET /raw/{id}` с
поддержкой HTTP Range-запросов, позволяя перемотку без перекодирования.

#### Scenario: Клиент перематывает браузерный файл
- **WHEN** клиент запрашивает `GET /raw/{id}` с заголовком `Range`
- **THEN** хост отвечает `206 Partial Content` с запрошенным диапазоном байт файла

### Requirement: HLS master-плейлист с рендициями дорожек
Для файлов в режиме `hls` `GET /hls/{id}/playlist.m3u8` SHALL отдавать
master-плейлист с одним вариантом видео и отдельной рендицией
(`#EXT-X-MEDIA:TYPE=AUDIO`) на каждую аудиодорожку и отдельной рендицией
(`TYPE=SUBTITLES`) на каждую текстовую дорожку субтитров, так чтобы плеер
переключал дорожки локально без перезапуска потока и без перекодирования видео
при смене аудио.

#### Scenario: Файл с несколькими аудиодорожками
- **WHEN** файл имеет две аудиодорожки и запрошен `GET /hls/{id}/playlist.m3u8`
- **THEN** master-плейлист содержит две рендиции `TYPE=AUDIO`, каждая со своим сегментным потоком

### Requirement: VOD-плейлисты рассчитаны заранее по полной длительности
Медиа-плейлисты видео, аудио и субтитров SHALL быть VOD, покрывающими всю
длительность файла (посчитанную заранее по метаданным), чтобы клиент мог
перематывать в любую точку без ожидания.

#### Scenario: Перемотка в конец файла
- **WHEN** клиент запрашивает сегмент видео ближе к концу длительности файла
- **THEN** хост запускает новую сессию транскодирования с этой позиции и отдаёт сегмент

### Requirement: Сегменты производятся сессиями транскодирования с ограниченным диапазоном
Хост SHALL генерировать HLS-сегменты сессиями (один процесс ffmpeg на
непрерывный диапазон, ограниченный по длительности), чтобы избежать
рассинхронизации на стыках сегментов внутри сессии; сегмент, не попадающий в
существующую сессию, SHALL запускать новую сессию с этой позиции. Число
одновременных сессий на файл SHALL быть ограничено, старые сессии SHALL
вытесняться по LRU; сессии, к которым долго не обращались, SHALL завершаться и
освобождать временные файлы.

#### Scenario: Запрошен сегмент вне покрытых сессий
- **WHEN** клиент запрашивает индекс сегмента, для которого нет активной сессии
- **THEN** хост запускает новую сессию транскодирования, начинающуюся с этого сегмента

#### Scenario: Простаивающая сессия завершается
- **WHEN** к сессии транскодирования долго не поступает запросов
- **THEN** хост завершает процесс и удаляет её временные файлы

### Requirement: Извлечение и доставка субтитров
Хост SHALL извлекать текстовые дорожки субтитров в формат WebVTT и отдавать их
двумя способами: как отдельный файл `GET /api/media/{id}/subtitle/{index}.vtt` и
как сегментированную рендицию внутри HLS (`/hls/{id}/subs/{track}/{index}.vtt`),
где каждый сегмент помечен временной привязкой к общей шкале плейлиста.
Графические (нетекстовые) дорожки субтитров SHALL быть помечены `textBased: false`
и недоступны для извлечения.

#### Scenario: Запрошены субтитры отдельным файлом
- **WHEN** клиент запрашивает `GET /api/media/{id}/subtitle/{index}.vtt` для текстовой дорожки
- **THEN** хост возвращает содержимое дорожки в формате WebVTT

#### Scenario: Запрошена графическая дорожка субтитров
- **WHEN** клиент запрашивает извлечение дорожки, помеченной `textBased: false`
- **THEN** хост отвечает 404

### Requirement: Дорожки из соседних файлов
Хост SHALL подхватывать субтитры и аудио, лежащие в соседних с видео файлах, по
шаблонам путей из конфигурации (`Player:SubtitleFiles`, `Player:AudioFiles`,
относительно папки видео, с плейсхолдером `{name}` — именем видео без
расширения). Такие дорожки SHALL добавляться в конец списка дорожек файла с
пометкой `external: true`, не изменяя номера вшитых дорожек, и SHALL
переоткрываться при каждом скане без перезапуска хоста.

#### Scenario: Рядом с видео лежит файл субтитров
- **WHEN** в папке видео есть файл, совпадающий с одним из шаблонов `Player:SubtitleFiles`
- **THEN** карточка файла содержит дополнительную дорожку субтитров с `external: true`

#### Scenario: Внешняя аудиодорожка требует HLS
- **WHEN** у файла в режиме `direct` появляется подхваченная внешняя аудиодорожка
- **THEN** файл раздаётся в режиме `hls`, чтобы внешняя дорожка была доступна как рендиция
