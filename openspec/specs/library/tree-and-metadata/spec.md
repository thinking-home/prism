# library/tree-and-metadata Specification

## Purpose
Библиотека хранит собственную структуру — дерево виртуальных групп с членством
файлов — и свободную мету, независимую от расположения файлов на дисках
хостов, чтобы пользователь мог организовать медиатеку по-своему и подписывать
записи произвольными атрибутами.

## Requirements

### Requirement: Дерево групп с вложенностью
Библиотека SHALL хранить группы с необязательным родителем (вложенность любой
глубины). Файл SHALL иметь возможность состоять в нескольких группах
одновременно. `GET /api/library/tree` SHALL отдавать все группы и всё членство
одним запросом, без пагинации.

#### Scenario: Файл в нескольких группах
- **WHEN** один и тот же файл добавлен в членство двух разных групп
- **THEN** `GET /api/library/tree` показывает членство этого файла в обеих группах

#### Scenario: Дерево запрашивается целиком
- **WHEN** клиент выполняет `GET /api/library/tree`
- **THEN** ответ содержит все группы (с родителями) и все связи членства за один запрос

### Requirement: CRUD групп
Библиотека SHALL поддерживать создание группы (`POST /api/library/nodes`,
обязательно непустое имя, опциональный родитель), переименование и перенос
(`PUT /api/library/nodes/{id}` — смена имени и/или родителя) и удаление
(`DELETE /api/library/nodes/{id}`, вместе со всеми потомками, их членством и
метой; сами файлы не удаляются — они просто выпадают из удалённых групп).
Перенос группы внутрь самой себя или своего потомка SHALL быть запрещён.

#### Scenario: Создание группы с родителем
- **WHEN** отправлен `POST /api/library/nodes` с именем и существующим `parentId`
- **THEN** создаётся новая группа с этим родителем

#### Scenario: Перенос ветки сменой родителя
- **WHEN** отправлен `PUT /api/library/nodes/{id}` с новым `parentId`
- **THEN** группа и всё её поддерево оказываются под новым родителем

#### Scenario: Запрещённый перенос внутрь потомка
- **WHEN** `PUT /api/library/nodes/{id}` пытается сделать родителем группы одного из её собственных потомков
- **THEN** запрос отклоняется с ошибкой, дерево не меняется

#### Scenario: Удаление группы с поддеревом
- **WHEN** удаляется группа, имеющая дочерние группы
- **THEN** удаляются вся ветка, её членство и её мета; файлы, состоявшие в удалённых группах, остаются в каталоге

### Requirement: Членство файла в группе
Библиотека SHALL поддерживать добавление (`PUT /api/library/nodes/{id}/items/{mediaId}`)
и удаление (`DELETE .../items/{mediaId}`) отдельного файла из группы без
проверки, что файл сейчас присутствует на каком-либо хосте (осиротевшее
членство — штатное состояние, не ошибка).

#### Scenario: Файл добавлен в группу до появления на хосте
- **WHEN** в группу добавляется id файла, которого сейчас нет ни на одном доступном хосте
- **THEN** членство сохраняется, запрос не завершается ошибкой

### Requirement: Свободная мета файлов и групп
Библиотека SHALL хранить произвольные пары ключ-значение отдельно для файлов
(`PUT/DELETE /api/media/{id}/meta`) и для групп (`PUT/DELETE /api/library/nodes/{id}/meta`).
`PUT` SHALL сливать переданные ключи с уже сохранёнными: значение `null` у ключа
SHALL удалять этот ключ, любое другое значение — создавать или заменять его;
ключи, не упомянутые в запросе, SHALL оставаться нетронутыми. `DELETE` SHALL
удалять всю мету сущности целиком.

#### Scenario: Частичное обновление меты
- **WHEN** у файла уже сохранены ключи `title` и `year`, и приходит `PUT` только с `year: null`
- **THEN** ключ `year` удаляется, `title` остаётся без изменений

#### Scenario: Мета сохраняется впрок
- **WHEN** `PUT` меты выполняется для id файла, которого нет ни на одном хосте
- **THEN** мета сохраняется без проверки существования файла
