# host/media-catalog Specification

## Purpose
Хост сканирует сконфигурированные папки с видео и предоставляет каталог найденных
файлов вместе со сведениями о самом сервере — на этом каталоге строятся все
остальные возможности хоста и клиенты (лаунчер, библиотека).

## Requirements

### Requirement: Сканирование папок с медиа
Хост SHALL сканировать список папок, заданных конфигурацией (`Player:MediaDirectories`)
и/или аргументами командной строки (`--media`/`--file`, дополняют список из
конфига, а не заменяют его), и строить из найденных видеофайлов каталог записей.
Относительные пути папок SHALL разрешаться относительно корня приложения.

#### Scenario: Файлы из нескольких папок попадают в один каталог
- **WHEN** сконфигурированы две папки с видеофайлами
- **THEN** записи файлов из обеих папок присутствуют в каталоге

#### Scenario: Папка передана аргументом командной строки
- **WHEN** хост запущен с `--media <папка>`, и в конфиге уже задана другая папка
- **THEN** в каталоге есть файлы из обеих папок

### Requirement: Сведения о сервере
Хост SHALL предоставлять `GET /api/info` со сведениями, достаточными клиенту для
работы без дополнительной настройки: доступность ffmpeg, выходной кодек,
параметры сегментации, список раздаваемых папок и число файлов в каталоге.

#### Scenario: Клиент запрашивает сведения о сервере
- **WHEN** клиент выполняет `GET /api/info`
- **THEN** ответ содержит `ffmpegAvailable`, `outputCodec`, `mediaDirectories` и `mediaCount`

### Requirement: Список файлов каталога не блокируется разбором метаданных
`GET /api/media` SHALL возвращать список файлов немедленно, используя ранее
закэшированные метаданные; файл, для которого метаданные ещё не разобраны,
SHALL возвращаться в переходном состоянии `pending` (`playable: false`,
`streamUrl: null`) вместо ожидания разбора.

#### Scenario: Новый файл виден в каталоге до завершения разбора
- **WHEN** в раздаваемую папку добавлен новый видеофайл, и фоновая доразборка ещё не обработала его
- **THEN** `GET /api/media` немедленно возвращает запись с `streamType: "pending"`, `playable: false`, `streamUrl: null`

#### Scenario: Ранее разобранный файл возвращается с полными данными
- **WHEN** `GET /api/media` запрашивается для файла, чьи метаданные уже есть в кэше
- **THEN** ответ содержит режим воспроизведения, длительность, видео/аудио кодек и списки дорожек этого файла

### Requirement: Карточка одного файла дожидается полного разбора
`GET /api/media/{id}` SHALL дожидаться завершения разбора метаданных файла
(включая ffprobe при отсутствии в кэше), прежде чем вернуть карточку. Если файла
с таким `id` в каталоге нет — ответ 404.

#### Scenario: Запрошена карточка ещё не разобранного файла
- **WHEN** клиент выполняет `GET /api/media/{id}` для файла без метаданных в кэше
- **THEN** хост выполняет разбор синхронно и возвращает карточку с полными метаданными в этом же ответе

#### Scenario: Запрошен несуществующий id
- **WHEN** клиент выполняет `GET /api/media/{id}` с id, которого нет в каталоге
- **THEN** ответ 404

### Requirement: Относительный путь файла в карточке
Каждая запись каталога SHALL содержать `relativePath` — путь файла относительно
корня той медиапапки, где он найден, с прямыми слешами независимо от ОС хоста.

#### Scenario: Файл лежит во вложенной подпапке
- **WHEN** видеофайл находится в подпапке раздаваемой директории
- **THEN** `relativePath` в его записи содержит путь от корня папки до файла с разделителем `/`
