# host/content-identity Specification

## Purpose
Каждый файл хост идентифицирует по содержимому, а не по пути, — это позволяет
внешним системам (лаунчеру, библиотеке) находить файл после переименования или
переезда и обнаруживать, чем заменилось содержимое по прежнему пути.

## Requirements

### Requirement: Контентный идентификатор файла
Хост SHALL вычислять идентификатор файла по содержимому (размер файла и хеш
краёв) при сканировании и использовать этот идентификатор как `id` записи во
всех API. Копии одного и того же контента SHALL получать одинаковый `id`.
Вычисленные отпечатки SHALL кэшироваться персистентно и не пересчитываться
повторно для не изменившегося файла (тот же путь, размер и время изменения)
после перезапуска хоста.

#### Scenario: Копии одного файла в разных папках схлопываются
- **WHEN** одинаковое по содержимому видео лежит в двух раздаваемых папках
- **THEN** в каталоге присутствует одна запись с этим id

#### Scenario: Перезапуск хоста не пересчитывает отпечатки
- **WHEN** хост перезапущен, а файлы на диске не менялись (тот же путь, размер, время изменения)
- **THEN** отпечатки берутся из персистентного кэша без повторного чтения содержимого файлов

### Requirement: Резолв файла по отпечатку
`GET /api/resolve` SHALL принимать размер и хеш содержимого и возвращать
карточку соответствующей записи каталога (в том же формате, что и
`GET /api/media/{id}`), либо 404, если файла с таким отпечатком в каталоге нет.

#### Scenario: Известный файл резолвится по отпечатку
- **WHEN** клиент выполняет `GET /api/resolve` с size/fingerprint файла, присутствующего в каталоге
- **THEN** ответ содержит карточку этой записи

#### Scenario: Неизвестный отпечаток
- **WHEN** клиент выполняет `GET /api/resolve` с отпечатком, которого нет в каталоге
- **THEN** ответ 404

### Requirement: Поиск преемника при изменении содержимого по прежнему пути
`GET /api/media/{id}/successor` SHALL возвращать id, под которым теперь известно
содержимое по последнему известному пути файла `{id}` — если по этому пути сейчас
лежит другое содержимое. Хост SHALL отвечать 404, если путь неизвестен, файла по
нему больше нет, либо содержимое по нему не изменилось.

#### Scenario: Файл по тому же пути перезаписан другим содержимым
- **WHEN** файл, ранее имевший id `A`, перезаписан по тому же пути другим содержимым с id `B`
- **THEN** `GET /api/media/A/successor` возвращает `{"id": "B"}`

#### Scenario: Содержимое по пути не изменилось
- **WHEN** запрошен преемник для id, чьё содержимое по последнему известному пути не менялось
- **THEN** ответ 404
