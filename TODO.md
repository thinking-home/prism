## 2. Множественные папки с видео на хосте
Сейчас хост сканирует одну папку (`Player:MediaDirectory`, `--media`). Нужно
поддержать **несколько корневых папок** (например, «Фильмы» на одном диске,
«Сериалы» на другом). Продумать: конфиг (список вместо строки), обратную
совместимость, `--media`, отображение в `/api/info` и инсталляторе.

## 3. Мультитрек HLS (master-плейлист) — для локального переключения дорожек
Сейчас Prism отдаёт медиа-плейлист с ОДНОЙ вшитой аудиодорожкой
(`segment/N.ts?audio=K`), а субтитры — отдельным эндпоинтом
`/api/media/{id}/subtitle/N.vtt`. Из такого вывода переключать аудио/субтитры на
плеере нельзя (в плейлисте нет `#EXT-X-MEDIA`-рендиций).

Нужно, чтобы Prism отдавал **HLS master-плейлист** с рендициями:
`#EXT-X-MEDIA:TYPE=AUDIO` (альтернативные аудио) и `TYPE=SUBTITLES` (WebVTT). Тогда
ExoPlayer в плеере сам показывает список дорожек и переключает их **локально, из
одного URL, без координатора**. Нюанс: в WebVTT переводятся только
текстовые субтитры; графические (PGS/VOBSUB) — только прожигом (отдельная задача).

## 4. Инсталлятор Windows (`Prism.Host.Setup`) — ЗАБЛОКИРОВАНО
Нужно делать на компьютере с Windows.

- **убрать галочку подтверждения лицензии**: шаг с текстом (MIT + сведения о
  вложенном FFmpeg) оставить информационным, но не требовать «I accept» для
  кнопки Next;
- **починить remember-паттерн**: при повторной установке путь к папке с видео
  не подхватывается из реестра (`HKLM\SOFTWARE\Prism\Host\MediaFolder`) — в
  диалоге снова показывается дефолт `C:\Videos` вместо сохранённого значения.
  Разобраться с порядком `AppSearch`/`SetMEDIAFOLDER`/costing (вероятно,
  set-свойства недостаточно, чтобы переопределить значение Directory до
  `CostFinalize`, или мешает значение по умолчанию из таблицы Directory).
- **enable/disable полей MQTT** в диалоге `PrismConfigDlg`: сейчас поля MQTT
  всегда активны (значения просто игнорируются, если галочка «установить
  лаунчер» снята). Хотелось бы серать их при снятой галочке — в WiX 6 дочерний
  `<Condition Action="enable|disable">` у `<Control>` не принимается (WIX0005),
  нужно найти актуальный синтаксис ControlCondition для v6.
- перенести версию пакета из хардкода в `Package.wxs` в свойство сборки.
- **проверка .NET 10 Runtime в инсталляторе**: программы теперь
  framework-dependent, нужен рантайм (ASP.NET Core — для хоста, Desktop — для
  лаунчера). Надёжной декларативной проверки нет: ключи реестра
  `HKLM\SOFTWARE\dotnet\Setup\InstalledVersions\...\sharedfx\*` отсутствуют, если
  рантайм пришёл с SDK (проверено — заблокировало бы саму дев-машину), а
  файловый `DirectorySearch` упирается в то, что `[ProgramFiles64Folder]` ещё не
  разрешён на этапе `AppSearch`. Правильное решение — **bootstrapper WiX Burn**,
  который сам ставит нужные рантаймы перед MSI (отдельный Bundle-проект). Пока
  полагаемся на встроенный диалог apphost'а («установите .NET…») + README.
